    Speed measurement

    — llama.cpp is the engine that runs a model. It ships with the app, so measuring and running need no download. It draws on any graphics card, or on the processor alone. Measuring a model keeps its real speed, and the estimates for other models on this PC are then corrected by it.
    NVIDIA's own engine is faster on NVIDIA cards. Once it is on this PC the app uses it by itself, and goes back to the built-in one if a model will not load with it.

    GGUF versions

    Which version should I pick?

    One model comes as several files. Each stores a weight in fewer bits: a smaller file needs less memory and writes faster, and below about 4 bits the answers get worse quickly.

    VersionBits per weight8B modelWhat to expect
    F16 / BF16
    16.0 bits 16.1 GB The original. Q8 answers the same.
    Q8_0
    8.5 bits 8.5 GB As good as the original.
    Q6_K
    6.6 bits 6.6 GB Very close to the original.
    Q5_K_M
    5.7 bits 5.7 GB A small loss. A step up from Q4.
    Q4_K_M
    4.9 bits 4.9 GB The usual pick: best balance.
    IQ4_XS
    4.5 bits 4.5 GB Like Q4, a little smaller.
    Q3_K_M
    4.0 bits 4.0 GB A clear loss. When Q4 does not fit.
    IQ3_XXS
    3.2 bits 3.3 GB Weak. For very large models only.
    Q2_K
    3.2 bits 3.2 GB Heavy loss. A last resort.
    IQ1_S
    2.0 bits 2.0 GB Mostly broken. Avoid.
    Reading a name Q4 about 4 bits per weight K spends more bits where they matter S · M · L small, medium, large mix IQ tuned with sample text: smaller at the same quality
    • Bigger model first. A larger model at Q4 usually answers better than a smaller one at Q8.
    • Leave room. The file is not all the memory: the conversation needs 1–2 GB on top.
    • Below Q3, only big models. Small models fall apart at 2 bits.

    Bits and sizes are llama.cpp's own figures for an 8B model. "What to expect" is common guidance, not a measurement: Test quality shows what a version really loses on this PC.
